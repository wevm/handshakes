# Google OAuth [Runs the device grant against Google]

## Overview

:::note
This integration has no automated test in this repository yet.
:::

On a device (such as a laptop), the client runs the device authorization grant (RFC 8628) against Google. In this grant, the user approves a code in a browser, and the client receives an access token and a refresh token. The client stores this grant, and refreshes it before the access token expires.

Google serves OpenID Connect discovery for the issuer `https://accounts.google.com`. The client reads the device authorization, token, and revocation endpoints from it. Google requires a client secret on the device grant, and allows few scopes for it.

| Setting        | Value                         |
| -------------- | ----------------------------- |
| Issuer         | `https://accounts.google.com` |
| Client type    | TVs and Limited Input devices |
| Client secret  | Required                      |
| Refresh tokens | Do not rotate                 |

## Walkthrough

:::steps

### Register the Client

Create an OAuth client of type "TVs and Limited Input devices" in the Google Cloud console. Keep the client secret in an environment variable, never in code or in argv.

### Create the Client

`Store.file` of `handshakes/node` keeps the grant in `~/.config/handshakes/grants`, shared by every process of the user. `clientSecret` goes with the device grant, the refresh, and the revocation.

```ts [userinfo.ts]
import { Client } from 'handshakes'
import { Store } from 'handshakes/node'

const client = Client.create({
  clientId: '<client id>.apps.googleusercontent.com',
  // Read from the environment, never from argv.
  clientSecret: process.env.GOOGLE_CLIENT_SECRET,
  issuer: 'https://accounts.google.com',
  scope: 'openid email',
  store: Store.file(),
})

// Runs the device grant on the first call in a terminal, then uses the stored grant.
const response = await client.fetch('https://openidconnect.googleapis.com/v1/userinfo')
```

### Approve the Code

The client prints the verification page and the user code to stderr. The user opens the page, signs in, and approves the code. The client polls the token endpoint at the interval of the server, then stores the grant.

:::

## Recipes

### Refresh and Revoke

Google refresh tokens do not rotate. A refresh response holds no new refresh token, so the client keeps the stored one. `client.revoke()` revokes the refresh token at the revocation endpoint, and deletes the stored grant.

```ts [logout.ts]
// Revokes the refresh token, and deletes the grant from the store.
await client.revoke()
```

### Scopes

The device grant of Google allows only a short list of scopes, such as `openid` and `email`. Google rejects a request for another scope, and `DeviceGrant.RejectedError` reports the error of the server. The Google documentation lists the allowed scopes.

### The CLI

`--client-secret-env` names the variable that holds the client secret. The CLI reads no secret from argv, and a [CLI profile](/cli/configuration) cannot name the variable.

```json [handshakes.json]
{
  "profiles": {
    "google": {
      "clientId": "<client id>.apps.googleusercontent.com",
      "issuer": "https://accounts.google.com",
      "scope": "openid email"
    }
  }
}
```

```sh
# Runs the device grant with the client secret from GOOGLE_CLIENT_SECRET
handshakes authorize google --client-secret-env GOOGLE_CLIENT_SECRET

# Refreshes the grant when it expires soon, which also needs the client secret
curl -H "Authorization: Bearer $(handshakes token google --client-secret-env GOOGLE_CLIENT_SECRET)" https://openidconnect.googleapis.com/v1/userinfo
```
